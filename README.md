# 卡厄思战斗采集器

用于记录一场战斗的开场、已加载配置和结算操作历史，供离线分析。**目前为试用版，已做离线检查，尚未完成新采集器的首次游戏实测。**

## 下载与使用

Windows x64 免安装包在 [Releases](https://github.com/slyzhydt/czn-battle-collector/releases)。新安装请选择 `czn-battle-collector-0.1.3-preview.zip`；已有 v0.1.2 可用较小的 `czn-wave-export-fix-0.1.3.zip` 覆盖更新。更早版本先安装 v0.1.2 兼容补丁。GitHub 自动生成的源码压缩包不含运行环境。

1. 解压整个工具包，双击 **启动采集.cmd**。
2. 正常进入战斗，等开幕效果结束、手牌出现，暂不出牌或结束回合。
3. 在工具中选 **1 记录新开场**，填写模式、角色和语言。
4. 显示读取完成并断开后，正常打完整场；失败也请保留。
5. 出现结算界面后先不点继续、领取或复活，切回工具选 **2 记录结算并导出**。
6. 将 `exports` 中对应 ZIP 交给收集人。不要把战斗数据上传到本仓库或 Issue。

首次先由一人采一场并确认能重放，再安排多人批量采集。完整说明见 [使用说明.txt](使用说明.txt)。

### 别人电脑上提示版本不对

运行包内运行 **版本检查.cmd**，或在新版采集器选 **3 检查游戏版本**。检查后把 `logs/version-check.json` 交给维护者，能看到游戏程序和资源清单分别是否匹配、实际与预期 SHA256、文件大小及更新时间。检查不连接游戏，无需进入战斗。

旧 v0.1.0 运行包可以从 Releases 下载小诊断补丁，将补丁中的 `version_report.py` 和 `版本检查.cmd` 放到 `collector.py` 同一目录后运行。报告只在本机生成，不自动上传；用户目录前缀会替换为 `%USERPROFILE%`，其他安装文件夹名仍保留。

“程序不同”和“资源不同”是两项独立结果。文件哈希不能直接证明是更新、不同渠道、热修复还是本地修改，需要结合对方的报告判断；不要修改 `profile.json` 跳过版本限制。

### 已核对的新客户端组合

v0.1.2 兼容补丁增加了程序指纹以 `0e5ba239`、资源清单指纹以 `adec4b24` 开头的组合，并额外核对主脚本块。26 处原生指纹和读取所依赖的 11 个模块已完成静态对照；新组合仍待首次实际采集确认。安装路径或脚本不同的其他组合不会自动放行。

对方已有旧采集器时，将兼容补丁解压覆盖到 `collector.py` 所在目录即可，保留原有 `runtime`、`vendor`、`data`。运行“版本检查.cmd”，应同时显示程序、资源清单和主脚本包匹配，再先采一场普通战斗作验证。采集包会保存本次实际匹配的版本标识；开场、结算跨版本时会拒绝配对。新版本原始记录仍需相应资源和规则重放后才能用于训练。

### 多波战斗提示“不是开场记录的那一场”

v0.1.3 修复了同场换波会改变当前战斗资源编号、导致旧版拒绝导出的问题。只在种子与进入时间相同、波次列表及索引相符、实例计数未回退、场景身份一致时允许编号变化；不同场次仍拒绝配对。

已有读取成功的数据不用重采。覆盖补丁后保留 `data` 文件夹，双击 **恢复导出.cmd**，或在菜单选 **4 从已有数据恢复导出**。工具只检查本地回执和数据，再写入 `exports`，不要求启动游戏，也不连接游戏。已有同名 ZIP 会保留；失败原因写入对应结束记录目录的 `export-error.json`。恢复导出不代表通过整场模拟验证或训练准入。

## 范围与限制

- 只支持 `profile.json` 指定的 PC 客户端及资源版本；不同版本会在连接前停止。
- 读取战斗工作表、已加载配置和有限现有缓存。没有抓包、代理、证书安装、自动打牌或主动加载未加载资源。
- 开场、结算分别短暂连接，完成后释放读取代码并断开；恢复回执不确定时须保持工具窗口打开，正常退出游戏。
- 原始数据保存在本机，没有自动上传。记录包含时间、阵容、打法及随机采集者编号，不应当作完全匿名数据。
- 开场预先划分训练组与留出组，同版本同种子同关卡的重试归同组。配对完成不代表已能训练，仍需资源核对与整场重放。
- 单次读取上限 1 MiB；不完整或超限会停止，不静默截断。其他模式和新角色尚不能保证完整覆盖。

本仓库仅包含采集器；不包含战斗模拟器、搜索算法、模型、训练集、原始战斗快照或游戏资源。

## 源码运行与打包

源码运行需要 Windows x64、Python 3.11，以及 `requirements.txt` 中的依赖。

```powershell
python -m pip install -r requirements.txt
python -B collector.py --self-check
python -B collector.py
```

只想使用工具请下载免安装包。源码依赖由开发者自行安装，程序不会自动安装依赖或提权。

在装有完整 Python 3.11 的 Windows 环境中生成本地运行包：

```powershell
python -B build_portable.py dist/collector
```

生成位置为 `dist/collector/battle-collector`；打包程序不联网，也不连接游戏。它需要本地 Python 的标准库、DLL 和依赖许可文件。

## 检查与权限

`python -m unittest discover -s tests -v` 检查采集器边界与数据配对，不连接游戏。`VALIDATION.json` 记录此前离线验证范围；这些检查不替代实机验收。

仓库初始为私有，仅所有者管理；不自动邀请协作者。自动检查使用只读仓库权限，代码检出依赖固定到提交。主分支保护需要在 GitHub 设置中实际启用，配置说明本身不代表已生效；以仓库设置及交付回读结果为准。

运行包校验值见 `SHA256SUMS`；依赖及许可见 `THIRD_PARTY.txt` 和运行包内许可文件。
